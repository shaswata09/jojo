# Third-party notices

Three kinds of third-party work are named here.

1. **Code jojo ships.** Every npm package compiled into the web app or the
   phone app. The licence text and copyright line of each one travel with the
   app itself, generated from the installed packages rather than typed (see
   "Where the full notices are"); this file summarises them and quotes the
   texts the credits page does not.
2. **Files kept in this repository that someone else made, or that are derived
   from someone else's work.** The robot model, the fonts on the phone, some UI
   components, a block of pdf.js's CSS, and the agent skills used while
   developing. Each is listed under "Vendored into this repository", with its
   terms, and with an honest note where the terms are not settled.
3. **Programs jojo TALKS TO and does not ship.** MarkItDown and a model server,
   each installed and run by the user and reached over an address the user
   supplies. Their notices are reproduced anyway, because a person running them
   deserves to see the terms without going to look.

## Where the full notices are

- **Web app.** The production build writes three files beside the bundle:
  `LICENSE.txt` (jojo's Apache-2.0 licence), `NOTICE.txt` (this repository's
  `NOTICE`) and `THIRD-PARTY-NOTICES.txt`. The last is generated by
  `jojo:licence-notices` in `web/vite.config.ts` from the packages the bundle
  actually contains — the same trace `jojo:credited-bundle` makes — and carries
  each package's own licence file and NOTICE file verbatim, the full Apache-2.0
  text once, and this file. On GitHub Pages they are at
  `https://shaswata09.github.io/jojo/THIRD-PARTY-NOTICES.txt` and beside it,
  and the Guide's Built with page links to them.
- **Phone app.** `mobile/src/screens/guide/third-party-notices.json`, generated
  by `node mobile/scripts/third-party-notices.mjs` from the phone's production
  dependency tree (the set `npm ls --omit=dev --all -w mobile` prints), is
  compiled into the app and shown on the phone's Guide → Built with →
  Licences. It holds each package's licence file and NOTICE, with the MIT, ISC
  and Apache-2.0 bodies printed once, and the native Android and iOS libraries
  from the committed `mobile/scripts/native-inventory.json` (see "Native
  libraries on the phone" below). A test regenerates it and fails when it is
  stale.

## Model servers

- **Projects**: vLLM — <https://github.com/vllm-project/vllm>; Ollama —
  <https://github.com/ollama/ollama>; LM Studio — <https://lmstudio.ai>; and any
  other server offering the same interface.
- **Used for**: the assistant, the "Ask the graph" box, scout scoring, and
  reading a job posting into a new application.
- **How it is used**: jojo speaks the OpenAI-compatible `/v1/chat/completions`
  shape over HTTP to an address the user configures in Settings. It requires no
  particular server, ships none of them, vendors no code from any of them, and
  sends nothing anywhere else. With no address configured, every one of those
  features falls back to worked examples or to arithmetic done on the device.
- **Licence**: not reproduced here, and deliberately. jojo neither bundles nor
  depends on any one of these — it speaks a protocol, and which program answers
  is the user's choice. Each is offered under its own terms by its own authors,
  which is where a person running one should read them.

vLLM, Ollama, LM Studio and OpenAI are the property of their respective owners.
jojo is not affiliated with, endorsed by, or sponsored by any of them. "OpenAI-
compatible" describes the shape of the HTTP request and nothing more.

## Bundled dependencies

Every npm package jojo imports, in the browser bundle, in the phone app and in
the toolchain, is credited in the app itself, on **Guide → Built with**, with
the installed version, the licence each package states and what it does here.
That page is generated from `web/src/components/guide/credits.ts`, which
records versions read from `node_modules` rather than the ranges in
`package.json`, on the grounds that a range describes a version nobody is
running.

The list covers what the build bundles, not only what `package.json` names:
the production build traces every module it emits back to its package and fails
if one is not credited, or is credited under a licence it does not state
(`jojo:credited-bundle` in `web/vite.config.ts`). The packages that arrive that
way, beneath the ones jojo imports, are listed in the next section.

The icon artwork is credited there too: Lucide (ISC) on the web, Feather (MIT,
Cole Bemis) for the icons Lucide carried over from it and for the whole of the
phone app's set.

On the phone, Guide → Built with names the packages the app is built from and
opens the full generated notices for all of them (see "Where the full
notices are"). That generated list, not the short stack list above it, is the
attribution of record for anyone reading the APK.

**Native libraries on the phone.** Besides npm packages, React Native and its
modules link native libraries into the Android app (Maven artefacts, through

standard library, OkHttp and Okio, Fresco, SoLoader, fbjni, Hermes, the
Firebase SDK and Play services, …) from `:app`'s release runtime classpath, and
24 iOS pods (the Firebase pods, GoogleUtilities, nanopb, PromisesObjC, and the
C++ libraries React Native fetches — Folly, glog, boost, fmt, double-conversion,
fast_float). On Android those C++ libraries are compiled into react-android's
`libreactnative.so` and are credited under it. Each entry carries the licence
its POM or podspec states, the LICENSE and NOTICE files inside the artefact,
and the `third_party_licenses` list Google's artefacts carry for what they
bundle. The list comes from `mobile/scripts/native-inventory.json`, which
`node mobile/scripts/third-party-notices.mjs --native` writes from Gradle and
the CocoaPods Pods tree; it has to be rerun after a native dependency change,
and the phone's notices test fails when `Podfile.lock` or the Android
dependency declarations no longer match it.

Still open: several closed-source Google artefacts state only the Android

> This work is based on "Sci-fi O.B. Robot Unit TH-ICC02 (animated)"
> (https://sketchfab.com/3d-models/sci-fi-ob-robot-unit-th-icc02-animated-6c0764c2bc4c4aaa8e03ba1653f455a6)

> (http://creativecommons.org/licenses/by/4.0/)

Changes made (CC BY §3(a)(1)(B)): the mesh is reduced from about 125,000 to
about 62,000 triangles; the six 4K textures are resized to 1024 px and stored as

one at the visor, which jojo draws its own eyes from. jojo animates the skeleton
itself. The script that makes every change is
`web/scripts/robot/prepare_model.py`; the result is `web/src/assets/jojo-robot.glb`.
The artist does not endorse jojo.
